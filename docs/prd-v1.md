# 剧本杀角色扮演小程序 PRD v1

## 1. 文档目的

本文档用于描述“剧本杀角色扮演小程序”第一版的产品范围、功能需求、版本边界和验收标准。

本文档面向甲方和内部开发团队，尽量避免技术细节，以功能、体验和交付标准为主。

## 2. 产品目标

第一版目标是完成一个可体验、可演示、可继续扩展的 AI 角色扮演小程序。

用户可以在一个固定剧本世界观中选择角色，与 AI 角色进行连续的文本流式对话。系统会围绕角色人设、剧本背景、用户记忆和羁绊关系生成回复，并提供基础的成长反馈、内容安全、支付额度和后台管理能力。

## 3. 第一版核心体验

第一版核心体验闭环：

```text
选择角色
  -> 查看角色详情
  -> 进入单 Agent 流式对话
  -> 系统记录会话和基础记忆
  -> 用户看到羁绊/情绪/成就反馈
  -> 用户可购买点数继续使用
```

## 4. 目标用户

### 4.1 C 端用户

希望在小程序中与剧本角色进行沉浸式聊天、探索剧情关系、获得陪伴感和角色互动反馈的用户。

### 4.2 admin 用户

项目内部运营或管理人员，用于查看会话、处理异常内容、查看基础统计和管理额度包。

## 6. 功能需求

### 6.1 微信登录

用户首次进入小程序时，系统应支持通过微信身份完成登录。

功能要求：

- 用户可通过微信登录进入小程序。
- 系统能够识别用户身份。
- 再次进入时可恢复登录态。
- 未登录用户访问核心功能时，应触发登录或提示登录。

验收标准：

- 首次进入可完成微信登录。
- 登录后可访问角色、聊天、我的等页面。
- 退出或重新进入小程序后，用户身份可正常恢复。

### 6.2 底部导航

第一版底部导航包含：

- 首页
- 对话
- 记忆
- 我的

功能要求：

- 用户可通过底部导航切换主要页面。
- 当前所在页面状态清晰。
- 不展示第一版不包含的入口。

验收标准：

- 每个底部 tab 均可正常进入。
- 页面无空白、无明显跳转错误。

### 6.3 角色列表与角色详情

第一版提供 3 个可互动角色，均属于同一个剧本世界观。

角色信息包括：

- 头像
- 昵称
- 身份
- 人设简介
- 剧本/世界观背景
- 初始关系
- 进入对话按钮

功能要求：

- 首页或角色页展示 3 个角色卡片。
- 用户可进入角色详情页。
- 用户可从角色详情页进入单 Agent 对话。

验收标准：

- 3 个角色均可展示。
- 每个角色详情信息完整。
- 从角色详情进入对话流程顺畅。

### 6.4 剧本世界观

第一版只提供一个基础剧本世界观。

功能要求：

- 三个角色共享同一个剧本背景。
- 每个角色有独立身份、人设和对话风格。
- AI 回复应围绕当前剧本世界观展开。
- 不做多剧本切换。
- 不做复杂剧本编辑器。

验收标准：

- AI 回复能体现剧本背景。
- AI 不应频繁跳出现代闲聊或脱离角色设定。
- 三个角色在同一世界观下表现出差异化身份和语气。

### 6.5 单 Agent 流式聊天

第一版只做用户与单个 AI 角色的文本流式对话。

功能要求：

- 用户可发送文本消息。
- AI 以当前角色身份回复。
- 回复必须支持流式展示。
- 支持连续对话。
- 支持会话历史恢复。
- 支持失败提示。
- 用户消息和 AI 完整回复需要入库。
- 不保存流式传输过程中的中间分片。

不支持：

- 语音输入
- 图片输入
- 多人实时聊天
- 群聊

验收标准：

- 用户发送文本后，AI 回复可逐段展示。
- 连续 20 轮基础对话不崩溃。
- 刷新或重新进入后，可查看历史会话。
- 数据库中可查到用户消息和 AI 完整回复。

### 6.6 会话历史

功能要求：

- 系统需保存用户和 AI 的主要会话记录。
- admin 可查看会话列表和消息详情。
- 用户可恢复自己的历史会话。
- 消息列表需要分页。

存储范围：

- 保存 user messages。
- 保存 assistant messages。
- 不保存 streaming chunk。

验收标准：

- 用户能查看自己的历史会话。
- admin 能按分页查看会话和消息。
- 长对话不会导致列表加载明显卡顿。

### 6.7 长期记忆

第一版提供基础长期记忆能力。

功能要求：

- 系统可从对话中抽取重要信息。
- 记忆可用于后续对话上下文。
- 记忆类型包括用户信息、关系状态、剧情状态。
- 用户端不提供可编辑记忆面板。
- admin 可处理异常或错误记忆。

验收标准：

- 用户换会话后，AI 能在合适场景召回关键事实。
- 错误记忆可由 admin 禁用或覆盖。
- 记忆不会直接暴露为复杂用户编辑页面。

### 6.8 羁绊/好感度

功能要求：

- 用户与角色互动后，可增加羁绊经验。
- 角色详情或聊天页展示羁绊等级/进度。
- 达到阈值后可升级。

验收标准：

- 用户对话后羁绊值可变化。
- 用户能看到当前角色的羁绊等级和进度。
- 升级逻辑稳定，不重复异常触发。

### 6.9 AI 情绪指示器

第一版情绪类型：

- Neutral
- Happy
- Sad
- Angry
- Thinking

功能要求：

- AI 回复可带情绪状态。
- 前端以简单标签或状态点展示。
- Thinking 可作为简单状态展示。
- 不做复杂动效。
- 不做表情包系统。

验收标准：

- AI 回复后可显示对应情绪。
- 无情绪时默认展示 Neutral。
- 情绪展示不影响正常阅读。

### 6.10 轻量对话分享图

功能要求：

- 用户可从对话页生成轻量分享图。
- 分享图包含角色头像、昵称、精选对话和水印。
- 支持保存到相册。
- 不做复杂 HTML 编辑。
- 不做多模板海报编辑。

验收标准：

- 用户可生成分享图。
- 分享图内容清晰可读。
- 可保存到相册。
- 长文本有合理截断或换行。

### 6.11 成就/称号

功能要求：

- 用户完成几次对话后，可自动解锁少量称号/成就。
- 我的页展示已获得称号/成就。
- 不做复杂成就树。
- 不做复杂图鉴页面。

验收标准：

- 达成条件后可解锁称号/成就。
- 我的页能展示已获得内容。
- 重复达成不会重复异常发放。

### 6.12 模型档位

用户端提供三个模型档位：

- 轻松
- 标准
- 沉浸

功能要求：

- 用户可以切换模型档位。
- 不同档位映射不同后端模型配置。
- 后端记录每次调用的档位、模型、token 和费用估算。
- 不同档位消耗不同点数。
- admin 可查看基础模型使用情况。

验收标准：

- 用户可看到并切换轻松、标准、沉浸三个档位。
- 切换后后端实际使用对应配置。
- 模型调用日志包含档位、模型和费用估算信息。

### 6.13 点数与额度包

用户侧额度单位统一叫“点数”。

第一版提供 3 个固定额度包。

额度包配置包括：

- 价格
- 获得点数
- 展示文案
- 上下架状态

功能要求：

- 用户可查看当前剩余点数。
- 用户可购买额度包。
- 不同模型档位消耗不同点数。
- 点数变化需要记录流水。
- admin 可配置额度包价格和点数。

验收标准：

- 用户能看到点数余额。
- 购买成功后点数增加。
- AI 调用后可按规则消耗点数。
- 余额流水可追踪来源和变动。

### 6.14 第三方聚合支付

第一版需要接入第三方聚合支付，并通过小程序拉起微信支付。

支付流程：

```text
用户选择额度包
  -> 创建订单
  -> 第三方聚合支付下单
  -> 小程序拉起微信支付
  -> 用户完成支付
  -> 支付成功后第三方回调
  -> 服务端验签
  -> 幂等更新订单
  -> 订单改为已支付
  -> 写入点数余额
  -> 写入余额流水
```

功能要求：

- 创建订单。
- 调用第三方聚合支付下单。
- 小程序拉起微信支付。
- 接收支付成功回调。
- 回调验签。
- 回调幂等处理。
- 防重复到账。
- 支付成功后增加点数。
- 写入余额流水。

不做：

- 实时透支
- 按人民币逐 token 扣费
- 复杂退款
- 发票
- 多渠道支付管理后台
- 复杂营销优惠

验收标准：

- 用户可完成额度包支付。
- 支付成功后订单状态更新。
- 支付成功后点数到账。
- 重复回调不会重复入账。
- 支付记录和余额流水可查询。

### 6.15 内容安全

功能要求：

- 用户输入发送前做关键词检查。
- AI 输出返回前做关键词检查。
- 命中后给出安全提示。
- 主要页面展示 AI 内容标识。
- 分享图包含 AI 内容标识或水印。
- admin 可查看异常会话或异常消息。

不做：

- 复杂风控模型
- 人工实时审核
- 正式实名认证
- 正式防沉迷

验收标准：

- 明显敏感内容可被拦截。
- 拦截时不继续自由生成风险内容。
- 用户能在主要页面看到 AI 内容标识。

### 6.16 简单 admin

第一版需要简单 admin，供内部使用。

功能范围：

- 会话列表
- 消息详情
- 异常标记
- 备注
- 基础统计
- 订单查看
- 余额流水查看
- 额度包配置
- 模型使用日志查看

不做：

- 复杂权限系统
- 运营配置中心
- 完整数据看板
- 第三方低代码后台

验收标准：

- admin 可查看会话和消息。
- admin 可标记异常并填写备注。
- admin 可查看订单、支付记录和余额流水。
- admin 可查看基础模型调用记录。
- admin 可配置 3 个额度包的价格和点数。
