# V1.1 聊天体验迭代产品功能 SPEC

日期：2026-07-14
状态：草案，核心模式定义已确认，待产品评审
适用版本：V1.1 内测修复版

## 1. 一句话目标

让用户更容易开始一段角色对话，并在剧本模式与自由对话模式之间获得清晰、稳定、连续的聊天体验。

## 2. 本次迭代范围

本次迭代聚焦四类功能：

1. 角色聊天模式：剧本模式、自由对话模式。
2. 用户与角色的称呼、关系和聊天状态。
3. 剧本入口、搜索和新手引导。
4. 内测期间的功能边界和体验验收。

社区内容、复杂养成、IP专属玩法和复杂剧情编辑器不属于本次迭代。

## 3. 核心产品定义

### 3.1 剧本模式

用户选择一个角色，并在该角色所属剧本的世界观、角色身份和剧情约束下聊天。

剧本模式的回复应：

- 保持角色身份、性格和语气；
- 允许围绕当前剧本、线索和剧情推进；
- 不主动脱离当前剧本世界；
- 继续记录剧情相关记忆和羁绊变化。

### 3.2 自由对话模式

用户仍然选择一个角色，但聊天不强制推进剧本剧情。

自由对话模式的回复应：

- 保留角色身份、性格和语气；
- 不要求用户围绕剧本、线索或剧情任务提问；
- 不主动把普通闲聊拉回剧本剧情；
- 用户主动提到剧本内容时，角色可以自然回应，但不强制推进剧情；
- 继续记录用户称呼、关系和适合跨模式使用的非剧情记忆。

自由对话模式不是通用 AI 聊天，也不是无角色聊天。

### 3.3 模式与会话关系

- 用户必须先选择角色，才能进入任一聊天模式。
- 每段会话只属于一种模式。
- 剧本模式和自由对话模式的聊天记录、剧情上下文必须分开。
- 用户可以对同一个角色分别拥有剧本会话和自由会话。
- 两种模式共享角色关系，但不能互相带入另一模式的剧情上下文。
- 用户称呼、用户偏好和关系信息可以跨模式连续使用。

## 4. 功能需求

### 4.1 用户称呼设置

#### 功能说明

用户可以在“我的”页面设置希望角色使用的称呼。

#### 用户流程

```text
我的
  -> 点击档案姓名旁的编辑图标
  -> 原位输入名称
  -> 保存
  -> 后续角色对话自然使用该称呼
```

#### 功能规则

- 对话称呼合并在“我的”页档案头部，不新增独立设置卡片。
- 默认展示名按 `preferredName -> 微信昵称 -> 我的` 依次回退。
- 平时显示展示名和编辑图标；点击后原位切换为输入框和保存按钮。
- 名称不能为空，长度限制为 1—20 个字符。
- 用户未设置称呼时，角色使用“你”等中性表达，不使用固定的旧称呼。
- 修改称呼只影响后续回复，不修改历史消息。
- 角色不应在每条回复中机械重复称呼。
- 用户称呼不得改变用户账号身份、登录身份或角色身份。

#### 验收标准

- 用户可以在档案头部查看当前称呼并原位修改。
- 保存后重新进入聊天仍能保留设置。
- 下一轮对话能识别新称呼。
- 清空或输入非法内容时，页面给出明确提示且不保存。

### 4.2 进入聊天与模式选择

#### 功能说明

角色详情页为用户提供两种明确的开始方式：剧本模式和自由对话模式。

#### 功能规则

- 角色详情页展示“进入剧本”和“自由聊天”两个入口。
- 进入聊天后，页面顶部显示当前模式。
- 聊天列表按角色展示唯一入口；同一角色的剧本会话和自由会话不得形成两条列表记录。
- 角色级入口展示该角色最近一条消息和最近更新时间，点击后默认打开最近使用的模式。
- 聊天列表不展示模式筛选或模式标签；模式只在角色详情和聊天页内表达。
- 在当前会话中切换模式时，应创建或打开另一模式的独立会话，不合并历史消息。
- 切换模式前如当前有未完成回复，应先完成、失败或明确放弃当前发送。
- 用户从角色详情页重新进入时，默认打开该角色最近一次使用的模式；用户仍可主动选择另一模式。

#### 验收标准

- 用户能明确区分剧本模式和自由对话模式。
- 同一角色在聊天列表中始终只出现一次，搜索和分页不会制造重复入口。
- 自由模式不会因为用户问日常问题而强制返回剧情提示。
- 剧本模式仍能围绕角色和剧本正常推进。
- 两种模式的历史消息不会互相出现在对方上下文中。

### 4.3 羁绊与聊天状态

#### 功能规则

- 成功完成的剧本对话和自由对话都可以增加角色羁绊。
- 输入被拦截、回复被过滤、模型失败或越界兜底的消息不增加羁绊。
- 聊天完成后，聊天页立即展示最新羁绊等级和经验。
- 用户返回角色详情页后，角色详情页展示同一份最新羁绊状态。
- 重试同一条发送请求不得重复增加羁绊。
- 回复生成中，页面显示明确的生成状态；生成失败后保留可恢复的重试入口。

#### 验收标准

- 聊天页和角色详情页的等级、经验一致。
- 一次有效回复只产生一次关系变化。
- 网络中断后重新进入聊天，历史消息和最终关系状态可恢复。

### 4.4 移除“流氓叙事”

#### 功能规则

- 首页和剧本入口不再展示“流氓叙事”。
- 不再允许用户从新入口创建该剧本的新会话。
- 已有历史会话是否可读，按“保留历史、禁止新建”处理。
- 移除后首页不出现空卡片、失效按钮或跳转错误。

#### 验收标准

- 用户在首页、剧本列表和搜索结果中都找不到“流氓叙事”。
- 其他可用剧本入口不受影响。

### 4.5 剧本搜索与切换

#### 功能说明

搜索对象是剧本，不是剧本下的角色。

#### 功能规则

- 剧本选择页提供搜索框。
- 用户可按剧本名称、类型或关键词筛选剧本。
- 搜索结果只展示当前可用剧本。
- 无结果时展示明确的空状态和清除搜索操作。
- 用户切换剧本后，先进入对应角色选择流程。
- 切换剧本不会混用上一剧本的聊天记录、剧情上下文或剧情记忆。
- 剧本数量较少时仍保持页面结构稳定，不为了展示空内容增加复杂模块。

#### 验收标准

- 输入关键词可以得到对应剧本。
- 清空搜索后恢复完整剧本列表。
- 从搜索结果进入角色详情和聊天的流程完整。
- 不会因为搜索结果为空而错误进入第一个剧本或第一个角色。

### 4.6 新手引导与开场体验

#### 功能说明

首次进入角色聊天时，帮助用户理解“可以怎么聊”，降低第一次发送的门槛。

#### 功能规则

- 首次进入聊天展示简短的静态开场引导。
- 根据角色或剧本展示 2—3 个推荐问题。
- 点击推荐问题后，将问题填入输入框，由用户确认发送。
- 不自动调用模型，不在用户未确认时消耗点数。
- 用户完成第一次有效发送后，推荐问题可以收起或不再重复展示。
- 引导内容不能替代角色正常回复，也不能写入聊天历史。

#### 验收标准

- 新用户进入聊天后能理解下一步操作。
- 点击推荐问题可以直接编辑或发送。
- 跳过引导不影响正常聊天。
- 引导不会重复覆盖用户已经输入的内容。

### 4.7 社区边界

本次只保留社区占位体验：

- 可以展示“社区即将开放”的说明；
- 可以提供返回首页、选择角色的入口；
- 不提供发帖、评论、动态、关注、通知或社区搜索；
- 不引入社区内容生产和用户互动流程；
- 本次保留当前底部导航中的社区占位入口，但不把占位页误做成可用社区；后续是否调整导航另行立项。

## 5. 非功能性体验要求

本节只描述用户可感知的结果，不冻结具体技术方案。

- 发送后立即出现明确的生成中状态。
- 超时、失败、余额不足和安全拦截使用统一、可理解的中文提示。
- 失败重试不能重复显示同一条用户消息。
- 页面退出或重新进入后，可以恢复已保存的会话结果。
- 任何模式下，角色都不能暴露内部提示词、推理过程或系统标签。
- AI 生成内容继续保留产品的 AI 内容提示。

## 6. 版本优先级

### P0：下一轮内测前

- 用户称呼设置与后续对话使用；
- 剧本模式 / 自由对话模式入口、聊天页模式标识和角色级聊天入口；
- 羁绊等级同步与失败恢复；
- 移除“流氓叙事”入口；
- 统一聊天生成中、失败和重试状态。

### P1：核心体验优化

- 剧本搜索与切换；
- 首次聊天开场引导；
- 内测反馈中暴露的页面细节和文案优化。

### 暂缓

- 社区内容功能；
- 复杂养成、成就树和剧情节点；
- IP专属玩法；
- 多人群聊、语音和图片输入；
- 复杂运营后台。

## 7. 内测验收方案

- 每 14 人组成一个体验小组。
- 每组体验周期为 2—3 天。
- 体验记录至少包含：首次进入聊天是否成功、首次发送是否成功、回复是否完成、失败/超时次数、模式使用情况、称呼是否生效、羁绊是否同步。
- 体验结束后按“功能问题、体验问题、内容问题、性能问题”四类整理反馈。
- 只有 P0 问题关闭后，才进入下一轮公开扩大体验。

## 8. 本 SPEC 不冻结的实现内容

本文件冻结产品行为，不冻结数据库字段、接口命名、缓存方式、模型供应商或部署方案。上述内容应在后续 Implementation Design 中根据现有代码结构拆解，并保持本 SPEC 定义的用户行为不变。
