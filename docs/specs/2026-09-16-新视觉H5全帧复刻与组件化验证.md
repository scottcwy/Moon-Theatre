## 6. 组件化边界

当前完成的是**渲染组件化**：

```text
index.h5.tsx
  └─ PilotFrame
       ├─ PilotSurface
       ├─ PilotText
       ├─ PilotMedia
       └─ PilotVector
```

这层解决的是：

- 统一坐标和 rpx；
- 统一颜色、描边、阴影；
- 统一图片和矢量资源加载；
- 统一 frame 注册和截图验证；
- 为后续业务组件提供稳定的视觉节点来源。

本轮没有把 `TopBar`、`TabBar`、`CharacterCard`、`ScriptCard`、`PrimaryButton` 等业务组件迁入 `packages/miniapp-ui`，原因是当前任务红线禁止改该包，而且这些组件的语义边界还应由产品/前端体系确认。

下一步语义组件化建议：

1. 以 `1:387/494/626` 抽 `ChatHeader`、`ChatComposer`、`ModeSwitch`。
2. 以 `1:863/1164` 抽 `TopBar`、`ScriptHero`、`CharacterCard`、`HomeTabBar`。
3. 以 `1:1766/1892/1987` 抽 `ProfileCard`、`LoginPrompt`、`LoadingPanel`。
4. 以 `1:1657/2325` 抽 `CharacterHero`、`BondPanel`、`DetailActionBar`。
5. 替换通用 spec 节点后，再评估迁入 `packages/miniapp-ui` 或新的生产组件层。

## 9. 迁移到 weapp 的判断

当前 H5 复刻可以迁到 weapp 的部分：

- `PilotFrame` 到 `PilotVector` 的 rpx 和 Taro 组件结构；
- 大部分烘焙 PNG；
- 颜色、圆角、描边和绝对位置；
- 文本 spec 和 frame registry。

不能直接迁的部分：

- `?frame=` 和 H5 location 读取；
- H5 copy config；
- `backdrop-filter` 等 H5 CSS；
- 当前 H5 默认 tabbar；
- 2.1MB+ 的 PNG 资源需要压缩、CDN 或分包；
- mock 数据需要替换为页面真实状态和接口。

结论：**H5 复刻可作为 weapp 视觉迁移源，但应从 `PilotFrame` 的通用节点继续抽成业务组件后迁移，不直接把 H5 页面文件复制到 weapp。**
