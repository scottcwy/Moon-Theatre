## 1. 目标与权威边界

管理员通过 Web 独立完成剧本与既有角色内容上新、用户管理、订单排查、充值和模型配置；一次完整内容上新不需要开发改代码、执行脚本或重新打包小程序。扩编 FastClaw 角色 Agent 仍属于版本化发布，需要同步共享清单、provisioning 和相关代码。

本文是上述后台改造的需求与行为契约。所有“必须”条款均为待验收需求，不表示代码已经具备。现有能力以 §2 的代码入口为证；新增数据结构、接口和状态随实现同步到权威文档，不得提前写成已上线能力。

- 当前 API：[API 契约](../api-v1.md)。
- 当前数据定义：[schema.ts](../../apps/api/src/server/db/schema.ts)。
- 当前架构：[技术开发架构与前后端文档](../技术开发架构与前后端文档.md)。
- 当前角色运行边界：[FastClaw 角色 Agent 架构](./2026-08-14-fastclaw-roleplay-agent-architecture-spec.md)。

本规格对“seed 为角色编辑源”等现有约束提出明确变更；角色 Agent 保持版本化固定集合，推理模型仍由 FastClaw Agent 配置唯一决定。代码落地前旧契约仍描述当前实现，落地时须同步修订旧文档。本文不宣称已取代运行中的实现。

## 3. 使用者、范围与非目标

`DECIDED`：少量可信管理员使用统一权限；同一管理员可编辑、发布、查看聊天与处理账户，不设多级审批。页面与接口都必须校验权限。

| 模块 | `REQUIRED` 能力 |
| --- | --- |
| 剧本 | 新建、编辑、搜索、分类、搜索词、封面、排序、发布、下架 |
| 角色 | 新建、编辑、归属、头像及视觉变体、展示资料、人设、开场提问、发布、下架 |
| 内容与素材 | 网页填写、固定模板 JSON 导入、素材上传与复用、展示预览、隔离试聊 |
| 用户 | 搜索、账户和使用概况、封禁、解封、直接查看聊天原文 |
| 订单与支付 | 搜索与详情、渠道状态核验、已支付未到账补发、渠道退款结果展示 |
| 充值与钱包 | 套餐维护、价格与点数、排序与上下架、人工点数调整、账户及流水查询 |
| 模型 | 现有档位的服务商、模型、启停、点数单价、运行参数、测试、发布和版本恢复 |
| 审计 | 管理操作、内容和配置发布历史、聊天原文访问记录、失败状态 |

非目标：任意 Word/PDF 自动解析、后台 AI 生成角色卡、复杂审批、多级权限、实时协同、可视化剧情树、定时发布、后台发起真实退款、删除用户、修改用户聊天或记忆、新增模型档位。内容生成继续使用现有角色卡生产工作流。

## 4. 页面与编辑契约

### 4.1 入口与信息组织

沿用 `/admin` 与 `/api/admin` 边界，提供中文界面。内容、用户、订单、充值、模型与审计有明确入口，原有支付、审核和关键词等能力继续可达。桌面浏览器支持完整操作；手机至少支持查看和紧急下架。

角色编辑页分为“展示资料”“角色人设”“开场引导”“预览与发布”。列表展示发布状态、是否有草稿变更和最近发布任务结果，三者不得混为一个状态。

### 4.2 字段及关联

| 对象 | 管理内容 | 不变量 |
| --- | --- | --- |
| 剧本 | 标题、简介、世界观、稳定 slug、分类、搜索词、封面、排序 | slug 唯一；发布后稳定标识不得因改名变化 |
| 角色展示 | 姓名、身份、简介、头像、可选男女头像、关系起点、排序、归属剧本 | 角色 ID 和 agent ID 稳定；agent 标识由系统维护，避免运营误路由 |
| 角色人设 | system/personality/scenario/safety/outputFormat 五字段 | 核心人设必填；系统安全底线和协议不可由内容覆盖，允许补充角色约束 |
| 开场引导 | script/free 各自的提问列表 | 与角色可用模式一致，非法项须在保存或发布前提示 |

字段沿用当前数据库和共享契约的类型、长度及枚举；新增字段须由服务端验证并同步数据契约。排序按现有范式；相同排序值必须有稳定次序。

- 一个角色最多归属一个剧本，也允许无剧本角色。有剧本默认支持 script/free，无剧本仅支持 free。
- 男女头像仅为视觉变体，共用身份、人设和记忆；现有客户端选择须兼容，新角色不依赖硬编码姓名表。
- 已发布角色允许改名、润色；更换归属剧本或换成另一个人物应新建角色，禁止复用旧身份承接用户数据。
- 首页首期管理目录字段及排序，不新增独立推荐位编排。后台配置的封面与头像须在对应入口实际生效，不能被旧本地映射无条件覆盖。

### 4.3 导入、素材与预览

固定 JSON 模板须有可识别的版本及字段说明。导入先校验和预览，只生成草稿；错误定位到对象与字段。重名不等于同一身份，更新既有对象须显式匹配稳定 ID，不得按姓名静默覆盖；不得静默部分导入。

素材支持直接上传、选择已有资源和替换，使用稳定 HTTPS 地址。上传类型、大小及尺寸限制须在界面与服务端一致约束，具体限值在实现接口契约中明确；失败不得留下可发布的无效引用。仍被发布版本引用的资源不得因替换而失效。

展示预览覆盖剧本卡片、角色详情及开场提问，目标是发现裁切和内容问题，不要求逐像素复制小程序。AI 试聊必须能使用草稿、重置上下文，且不进入真实用户会话、记忆、扣点、羁绊或成就。模型调用成本应可追踪，不能把“不扣用户点数”写成“无推理成本”。

## 5. 草稿、发布与恢复

### 5.1 版本及状态语义

| 概念 | 行为契约 |
| --- | --- |
| 草稿 | 保存后的编辑版本，对公开接口和正式聊天不可见；可存在于已上架内容旁 |
| 已发布版本 | 经发布完成并被正式读取的不可变快照，包含关联素材和运行人设版本 |
| 上下架 | 决定公开可见性和新请求是否允许，与是否存在草稿独立 |
| 发布任务 | 至少能表达处理中、成功、失败及恢复待处理；超时或结果未知不得当作成功或确定失败 |
| 历史恢复 | 将旧发布内容恢复成草稿，再按正常校验和发布流程生效；不回退用户数据 |

每次保存校验编辑基准版本，冲突时提示刷新或人工合并，禁止静默覆盖。发布输入固定为选定草稿版本；发布期间再次编辑不能改变该任务内容。同一发布对象禁止并发激活相互覆盖。

### 5.2 发布不变量

1. 发布前展示变更差异与必填字段、素材、归属、agent 可访问性和运行约束的检查结果。
2. 剧本首次发布可携带选定的一批角色，至少一个角色可用；以后可单独新增、更新和下架角色。首期不发布纯预告剧本。
3. 保存不改变线上；只有展示资料和实际运行人设均就绪，发布才成功。正式请求使用完整版本，不能读到新展示加旧人设等半发布组合。
4. 业务库和 FastClaw 无共同事务，必须显式处理部分成功、并发请求和恢复。保持稳定角色/agent 身份不能以删除重建用户运行数据实现。
5. 发布失败保留原线上版本可用、保留草稿和原因，支持幂等重试；客户端断线或重复点击不能重复创建角色、agent 或发布版本。
6. 发布任务及恢复状态必须持久化。进程重启后可识别未完成任务，依据实际版本恢复或补偿；不允许把未知状态清零后重新发布。
7. 发布成功后新请求使用新版本，已开始生成的请求完成原版本。内容更新保留历史消息和记忆；版本恢复同样遵守此边界。
8. 禁止运行时未知 agent 静默回退到其他人物。就绪检查基于有效已发布角色检查映射和运行配置，合法增减角色不导致固定数量误报。

内容版本固定约束本回合采用的角色卡与剧本快照，不增加历史或记忆的版本隔离维度。同一用户、角色和会话下，旧版本期间产生的历史及记忆继续按既有用户隔离、共享/剧本 scope、检索及压缩规则参与新版本生成；不保证每条历史或记忆逐条注入。恢复旧内容后，新版本期间产生的用户数据同样保留并按上述规则可见。恢复内容不等于恢复用户时间线。

发布界面展示进度和可追踪结果；30 秒后仍未完成须明确显示“处理中”或确定的失败原因，30 秒不是跨系统操作的成功保证。

### 5.3 下架、删除和存量纳管

- 下架角色退出公开列表和可用详情入口，停止新建会话与新消息；下架剧本对其所属角色产生同样限制。已接受的在途请求可按原版本结束。
- 历史聊天仍可查看，显示当前不可继续聊天的状态；恢复上架不删除或重建用户历史。
- 仅未发布且无用户关联数据的草稿可删除；已发布对象只允许下架。删除不得破坏历史版本引用的素材。
- 现有内容作为首个已发布版本纳管，保留角色、剧本和 agent 标识及用户关联。seed、部署和旧 provisioning 必须遵守后台编辑来源，重复执行不得覆盖运营修改。

## 6. 用户与聊天查看

用户列表和详情支持搜索、状态、账户余额、订单及使用概况，关联查看会话与消息；聊天按用户、角色、模式和时间提供可定位的分页读取。

`DECIDED`：所有管理员可直接查看聊天原文，不需要投诉前提、审批或填写查看原因。记录访问者、时间、目标用户/会话和请求结果；审计记录不复制整段聊天原文。普通用户不得通过管理接口访问他人数据。

封禁后现有登录凭据不得继续授权新的用户业务请求；已接受的请求可结束。解封恢复正常权限。不提供删除用户、改写聊天或记忆入口。管理员权限仍受白名单及用户状态校验，不能仅凭曾经登录放行。

旧 Memories 导航及页面须退场，直接调用旧记忆 PATCH 接口也必须拒绝且无写入副作用；仅隐藏入口不算完成。本期不新增记忆只读管理页，聊天原文查看不包含编辑或禁用记忆的权限。

## 7. 订单、支付、充值与钱包

### 7.1 订单核验与补发

订单按用户、订单号、状态及时间检索，详情关联支付记录和点数流水。主动核验必须使用支付渠道可信结果，核对商户订单、交易身份、金额和成功状态；查单超时或未知时显示未确认，不得强制置为已支付。

补发只针对经验证已支付但未到账订单，复用正式入账流程和订单级幂等标识；并发通知、管理员补发及重试合计只入账一次。已入账返回既有结果，未支付、金额不符或退款状态不满足条件时拒绝补发并说明原因。

首期只读展示可信渠道退款结果，不提供退款发起或任意改订单状态。退款的点数追回、已消费点数处理不在本次自动化范围；不得因显示退款状态而擅自改钱包。无法取得可信渠道结果时明确显示能力不可用或状态未确认。

### 7.2 套餐与人工点数调整

套餐支持创建、编辑、推荐标记、排序和上下架；金额使用整数分，点数使用整数。价格、点数及字段范围由服务端验证。变更只影响新订单，历史订单以购买时金额、点数快照为准，不能取当前套餐值重算。

人工加减点数必须填写非空原因，并显示目标用户、调整量与结果余额以供确认。每笔操作记录管理员和幂等标识；钱包余额与流水原子更新，重复请求仅产生一笔调整。并发消费或扣减下不得出现负余额，拒绝的调整不得留下成功流水。

同一幂等标识、相同操作者/目标用户/方向/金额/原因的重放返回原操作结果；上述任一项不同必须明确报冲突，不得静默返回旧结果或执行第二笔调整。并发请求也遵守该边界；标识生成、请求规范化和冲突响应结构在接口契约中明确。

人工调整不能伪装成用户充值或已支付订单；保留既有 recharge/consume/adjust 语义，列表可区分并追溯。不得提供无流水的余额直接覆盖入口。

## 8. 模型与计费配置

首期保留 casual/standard/immersive 三档；管理服务商、模型、启停、每次消耗点数和支持的运行参数。系统安全、协议与已确认运行边界不能被自由参数覆盖；thinking 关闭、工具限制等既有约束继续有效，变更须另行修订对应契约。

- 保存为配置草稿；发布前测试实际服务商连接、模型调用和运行约束。测试失败禁止发布；测试不修改正式配置或扣用户点数。
- 推理模型只由 FastClaw Agent 配置决定；chat adapter 请求体不得携带请求级 `model`。业务档位只承载计费与展示语义，发布推理模型变更必须发布相应 Agent 配置并重新通过 runtime-spec 检查。
- 以同一用户与 `clientMessageId` 标识已接受回合；首次接受时持久固定内容版本、计费档位与计费单价。失败重试、生成租约过期后接管及进程重启都沿用该快照，不读取重试时的新计费配置替换它。具体持久化结构在实现契约中明确。
- 按生成尝试保留扣费与退款流水；失败尝试退回对应扣点。失败退款后允许重试按原单价再次扣费：若原单价为 A，最终成功的回合净支出恰为 A，全部尝试失败且退款完成时净支出为 0；成功回合的重复请求只重放既有结果，不再扣费或重新生成。新回合才采用新配置及单价。
- 扣费或退款结果未知、退款失败时须保留可恢复状态，核对并幂等恢复，不能吞掉失败或宣称退款完成；在恢复完成前不能把账目口径当作已满足。恢复、接管及重试须防止重复扣退，具体机制在实现契约中明确。
- 在途请求保持原配置；禁用档位后新请求明确拒绝，不能暗中改档。保留发布历史、差异和恢复入口；恢复仅影响后续请求。
- 用量记录关联实际 provider/model、所用配置版本与实际点数，后台显示值必须可与运行结果核对。
- 密钥只支持安全替换与脱敏展示；响应、日志、审计和版本快照不得含可恢复的明文密钥。旧配置恢复需要可用凭据，凭据失效时须提示并重新测试。

## 9. 权限、审计与运行边界

微信扫码登录加管理员白名单是目标方案。网站扫码登录资质与小程序身份映射需核实，不能直接假定两类 OpenID 相同。服务端建立可退出的管理会话；Cookie 会话须防跨站写入，登录回调校验关联状态。生产不允许开发绕过或扫码失败后匿名降级。

现有 Basic Auth 不是新管理员身份，不能单独授权内容、资金和模型操作；是否保留为部署外层门禁须在部署契约明确。未登录、非管理员和配置不可用须分别可辨识；服务端渲染、管理接口、文件上传、预览、试聊和恢复均执行相同授权边界。

审计覆盖操作者、对象、动作、时间、请求/任务标识、版本或变更摘要及结果；资金操作记录原因与流水关联。失败与重试可追踪，密钥和大段提示词、聊天原文不直接复制进通用日志。数据库业务成功但审计失败的处理必须在实现契约明确，不能把未审计的资金操作当作完整成功。

聊天原文仅在本次访问审计持久化成功后返回；审计失败时拒绝返回原文并给出可辨识的依赖故障。资金及发布操作必须能区分未提交、已提交但审计待恢复、完整成功与结果未知；已提交业务不能因审计重试而再次执行。实现设计须在编码前明确故障响应、结果查询、幂等重试及审计恢复方式，并覆盖进程重启；未完成审计不得显示完整成功。本文不指定事务或 outbox 等机制。

规模基线为 100 个剧本、1,000 个角色、5 名管理员。列表分页与搜索，不一次下载全部消息和历史版本。失败及恢复待处理在后台明确展示，首期不接外部消息通知；运维可按请求或任务标识定位错误。

## 10. 数据、接口与实现约束

扩展现有模块、鉴权和请求/错误处理范式，不为后台另造平行业务账本。以下为必须满足的逻辑契约，不预定尚未审查的表名、路由和 JSON 结构。

| 边界 | 必须表达的数据或行为 |
| --- | --- |
| 内容写入 | 稳定对象 ID、基准版本、校验错误；保存结果不得暗含发布 |
| 发布与恢复 | 固定版本、幂等标识、持久任务、实际结果及恢复入口 |
| 资金写入 | 目标用户/订单、可信支付依据或调整原因、幂等标识、流水关联 |
| 模型发布 | 已测试草稿版本、实际运行配置、计费快照、凭据引用 |
| 所有读写 | 管理授权、分页/字段边界、可区分的无权限/不存在/冲突/校验失败/依赖不可用 |

当前 API 以 [api-v1.md](../api-v1.md) 为准；新增路由和数据结构在实现时同步更新，不在本文复制现有 schema。正式接口不得暴露草稿、提示词或密钥。

以下实现设计必须在编码前具体化并接受技术审查，不能以本需求冻结替代设计完成：跨业务库/FastClaw 的版本激活与补偿机制、稳定 agent 下的版本固定、档位计费与 Agent 模型配置核对、回合快照及扣退账恢复、审计故障响应与恢复、人工调整幂等冲突、扫码身份映射与会话、渠道查单、素材存储及限制。设计须满足本文不变量，不能借技术选择缩减已确认范围。

## 11. 验收矩阵

以下为 `REQUIRED / PLANNED`，全部通过方可把本规格实现状态更新为 `VERIFIED`。自动化测试、联调和人工验收须记录结果及证据入口；仅现有 harness 通过不能证明后台实现完成。

| ID | 可操作场景 | 通过标准 |
| --- | --- | --- |
| AC-01 | 管理员从零创建剧本、上传素材和创建角色，预览试聊后发布 | 无开发操作；刷新小程序可发现并与正确角色聊天 |
| AC-02 | 修改线上角色并保存；两个编辑页先后保存 | 草稿不影响正式展示及推理；旧基准写入明确冲突 |
| AC-03 | JSON 含错误、重名或重复提交；上传非法素材 | 字段错误可定位、无静默部分导入或覆盖；服务端拒绝无效素材 |
| AC-04 | 对草稿试聊并重置 | 正式会话、记忆、余额、羁绊和成就无增量，成本可追踪 |
| AC-05 | 发布期间分别注入同步失败、激活失败、进程重启和客户端超时 | 线上不读半版本，原版本可用；状态可追踪恢复；重试不重复创建 |
| AC-06 | 在 v1 生成期间发布 v2，继续原会话，再恢复 v1；各版本期间分别产生可检索的历史及记忆 | 在途按原快照、新回合按当前发布版本；角色/agent 身份不变；历史及记忆不清空，并按原用户/scope 规则继续可见，不按内容版本隔离；其他用户或不匹配 scope 的数据不可见 |
| AC-07 | 未更新共享清单时新增第 20 个角色；按版本更新清单并 provisioning 后再次发布；另构造缺失或重复 agent | 未版本化扩编被拒绝；版本化扩编后 readiness 通过；错误映射明确失败，不静默回退其他人物 |
| AC-08 | 下架剧本/角色并访问旧入口，随后重新上架 | 公开入口及新聊天受限，历史可读，恢复后身份与用户数据保持 |
| AC-09 | 纳管后改名、改人设、换图，再执行初始化和部署同步 | 稳定 ID、运营修改和用户关联不变；素材在小程序实际生效 |
| AC-10 | 未登录、普通用户、已退出或被封禁管理员访问页面/API/上传/试聊 | 全部服务端拒绝；正式接口无草稿、提示词及密钥泄漏 |
| AC-11 | 管理员直接查看聊天，封禁用户后使用旧用户凭据 | 无需填写查看原因；访问留痕；被封禁用户的新业务请求拒绝，解封可恢复 |
| AC-12 | 渠道查单成功/未知/金额不符；回调与补发并发重试 | 仅可信匹配成功可补发，最终只入账一次；未知不当作支付成功 |
| AC-13 | 下架或调价套餐后查看旧订单并创建新订单 | 旧订单金额和点数保持；新订单按新值；下架不可新购 |
| AC-14 | 人工调整同 key 同参数重试；分别变更操作者、用户、方向、金额、原因复用 key；与消费/扣减并发 | 相同请求返回原操作结果，只产生一笔调整；任一参数不同明确冲突且无第二笔调整；余额不为负，成功操作关联流水和审计；无原因拒绝 |
| AC-15 | 配置错误 Agent 模型、有效新 Agent 模型和禁用档位，发布时存在在途请求 | 错误测试阻止发布；请求体不含 `model`，实际调用模型来自配置 Agent且与用量记录一致；新旧请求边界正确 |
| AC-16 | 原单价 A 的回合失败退款后发布计费档位/单价 B，用原 clientMessageId 重试；覆盖租约接管、重启、成功后重放、全部失败及扣退结果未知 | 原回合始终使用首次内容/计费/价格快照；最终成功净扣 A，全部失败退款完成净扣 0；各尝试扣退流水可核对，成功后重放无新扣费或生成；未知/失败可幂等恢复且不虚报完成；新回合采用 B |
| AC-17 | 检查密钥接口、日志、版本恢复及退款展示 | 明文密钥不返回或落日志；恢复前测试凭据；退款展示不擅自改钱包 |
| AC-18 | 载入规模基线并从桌面与手机访问；任务超过 30 秒 | 分页搜索可用；桌面完成全流程，手机可查看及下架；无虚假成功提示 |
| AC-19 | 聊天原文访问、资金调整及内容/模型发布时注入审计存储故障，并覆盖业务已提交、客户端超时和进程重启 | 原文未获持久访问审计时不返回；写操作结果可查询并区分提交/审计恢复状态，不虚报完整成功；重试与恢复不重复变更业务，恢复后审计可关联原操作 |
| AC-20 | 访问旧 Memories 页面并直接调用旧 PATCH 写接口 | 导航和页面退场；接口明确拒绝，旧业务库与 FastClaw 记忆均无写入副作用 |

代码落地时按改动运行 API 测试、typecheck、后台交互验证和小程序回归；涉及 FastClaw 则增加对应 Go 验证及真实链路版本隔离测试。仓库收口另遵守 `AGENTS.md` 的 harness 验证，不用文档检查代替行为验收。
