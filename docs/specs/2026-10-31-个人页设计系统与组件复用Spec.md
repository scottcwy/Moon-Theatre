# 个人页设计系统与组件复用 Spec

> 状态：`FROZEN / IMPLEMENTED`
> 冻结日期：2026-10-31
> 适用范围：`apps/miniapp/src/pages/profile`、共享导航组件及 `packages/miniapp-ui`

## 1. 目标

让“我的”页在登录、未登录、加载、错误和空数据状态下遵循现有设计系统，复用已有组件能力，并与首页、聊天、社区共用一致的底部导航 footer。

## 2. 已确认事实

- “我的”页已经复用 `PageShell`、`StageTabBar`、`CharacterAvatar`、`PrimaryButton`、`Badge`、`AchievementIcon`、`NoticeBlock` 和 `EmptyState`。
- 共享 UI 包已经提供 `BalancePanel`、`QuotaBalanceHero`、`PageSection`、`Surface`、`BottomTabBar` 等能力。
- 当前“我的”页在页面级 SCSS 中重新定义了 `.theater-tab-bar` 的高度、内边距、选中态和图标尺寸，导致共享 footer 的视觉几何被页面覆盖。
- 成长记录的“称号 + 成就列表”是当前个人页的页面组合，没有确认存在可直接替换的单一共享业务组件。

## 3. 范围与边界

### 3.1 REQUIRED

- 保留 `StageTabBar` 作为首页、聊天、社区、我的四个主页面的 footer 实现。
- 个人页不得覆盖 `StageTabBar` 的高度、内边距、选中态装饰、图标尺寸、标签字号和定位规则。
- 个人页新增或调整的颜色、间距、圆角、阴影和字号优先引用 `packages/miniapp-ui/src/styles/tokens.scss` 的语义 token。
- 余额区域先评估 `BalancePanel` 与 `QuotaBalanceHero` 的适配；只有现有 API 无法表达个人页已确认视觉时，才增加最小变体或保留页面组合。
- 成长记录继续使用 `Badge`、`AchievementIcon`、`EmptyState` 等现有组件组合，保持标题、成就描述、解锁状态和空态行为不变。
- 保持现有业务行为：编辑称呼、保存失败提示、续灯跳转、退出登录、去选角色、查看聊天及 AI 内容提示。

### 3.2 DECIDED

- 本 SPEC 不要求把每个页面局部结构都抽成共享组件。
- 单页专属的成长记录不因“组件数量”而新增通用抽象。
- 共享组件只有在至少两个页面复用，或拥有稳定业务语义与多状态行为时，才考虑扩展到 `packages/miniapp-ui`。

### 3.3 非目标

- 不重做个人页的信息架构或视觉方向。
- 不修改 API、数据模型、登录流程、点数计费和导航路由。
- 不把现有 `StageTabBar` 替换成另一套 footer 实现。
- 不在本 SPEC 中规定 Figma/Pen 设计稿的新增页面。

## 4. 组件复用映射

| 个人页区域 | 规范实现 | 页面允许的定制 |
| --- | --- | --- |
| 页面容器与滚动 | `PageShell` | 页面背景、内容间距和状态布局 |
| 底部导航 | `StageTabBar` | 仅传入 `selected`，不得重写其几何 |
| 用户头像 | `CharacterAvatar` | 尺寸和页面上下文色彩 |
| 称呼编辑 | `Input`、`IconButton`、`PrimaryButton` | 文案、局部布局和页面主题色 |
| 灯火/点数 | 优先 `BalancePanel` 或 `QuotaBalanceHero` | 通过已有 props 或最小变体适配 |
| 称号 | `Badge` | 语义 tone 和页面排列 |
| 成就 | `AchievementIcon` + 页面列表组合 | 列表间距、状态文案和局部皮肤 |
| 错误/空态/说明 | `StatusStateCard`、`EmptyState`、`NoticeBlock` | 文案和容器位置 |

## 5. 实施阶段

### 阶段 A：共享 footer 收敛

移除个人页对 `.theater-tab-bar` 及其子元素的几何覆盖，保留不会改变共享布局契约的页面主题样式。确认四个主页面使用同一套 footer 结构、尺寸和交互。

### 阶段 B：余额区域适配评估

以当前个人页视觉和交互为验收基准，对比 `BalancePanel`、`QuotaBalanceHero` 的 props 与结构。如果直接复用会丢失已确认行为或造成复杂条件分支，则为现有组件增加最小、可命名的变体；否则直接替换页面私有余额结构。

### 阶段 C：token 与状态收口

将个人页新增的魔法颜色、间距和尺寸替换为语义 token；逐一检查加载、未登录、错误、空成长记录和已登录有数据状态，不改变现有业务分支。

## 6. 验收标准

- `StageTabBar` 在首页、聊天、社区、我的四页的 computed 几何一致：位置、宽高、内边距、图标尺寸和选中态容器不由页面覆盖。
- 个人页所有状态仍能渲染对应共享组件：loading 使用 `ProfileLoadingCard`，未登录使用头像/徽章，错误使用 `StatusStateCard`，空成长记录使用 `EmptyState`。
- 余额区域的最终实现有明确组件归属：直接复用现有组件，或记录一个最小变体及其理由；不得保留无理由的重复余额组件。
- 个人页新增样式不引入与 token 冲突的同义颜色、间距和圆角常量。
- 相关单元测试、E2E 布局检查和截图审查通过；E2E 若受微信开发者工具会话或 viewport 限制阻塞，必须记录为 `BLOCKED`，不得标记为通过。

## 7. 数据与接口

本 SPEC 不新增数据或接口。个人资料、点数、称号和成就的接口契约以 [`docs/api-v1.md`](../api-v1.md) 为准。

## 8. 变更控制

若实现需要新增共享组件、改变公共 props 或改变个人页业务行为，必须先更新本 SPEC 的组件映射与验收条目，再实施代码变更。
