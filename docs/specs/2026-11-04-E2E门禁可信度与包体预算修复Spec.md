# Miniapp E2E 门禁可信度与包体预算修复 Spec

> 状态：`FROZEN / VERIFIED`
> 审计日期：2026-11-04 · 基线提交 `f49f0ce`
> 适用范围：`apps/miniapp` 的 E2E、视觉矩阵、构建产物标识和包体校验
> 上游依据：`2026-10-29-UI视觉差异审计与修复Spec.md`、`2026-10-19-第二份合同UI前端更新Spec.md`、`2026-08-17-chat-history-pagination-spec.md`

## 1. 目标

修复当前 E2E 和包体门禁中会误报、假绿或无法启动的问题，使门禁结论满足以下语义：

1. 必需元素缺失时，报告具体缺项，而不是抛出与根因无关的迭代错误。
2. 角色详情、首页和聊天断言对应当前真实页面结构与真实 API 状态。
3. 真实数据 E2E 只接受与本次运行目标一致的构建产物。
4. `fallback`、本地模式、流式错误和 skip 均不能冒充成功。
5. 默认视觉矩阵能够通过配置校验并启动。
6. “主包 2 MiB”只表示整个可上传主包，不表示资源目录大小。

## 2. 范围与边界

### 2.1 REQUIRED

- 修复 P1-5、P1-6、P1-7、P1-8、P1-9、P1-10、P1-12、P2-13。
- 为上述行为增加或更新可执行验证。
- 代码变更、Spec 状态和相关 E2E 说明在同一提交内同步。

### 2.2 非目标

- 不调整视觉像素阈值来换绿灯。
- 不修改聊天业务协议、消息成功判定规则或 API 返回语义。
- 不为真实 E2E 伪造长会话，也不写生产数据制造测试状态。
- 不直接编辑 `apps/miniapp/dist/**` 生成文件。
- 不在本 Spec 内继续收敛视觉差异；视觉门禁仍按既有阈值判定。
- 不删除旧 13 帧证据；只修复其矩阵配置契约。

## 3. 状态词与门禁语义

单个检查使用以下状态：

- `passed`：必需检查真实执行并满足断言。
- `failed`：执行了检查，但断言失败。
- `skipped`：检查未执行，原因是环境或数据缺失。

整体结果使用以下状态：

- `passed`：所有必需检查均为 `passed`。
- `partial`：没有失败，但至少一个必需检查为 `skipped`。
- `failed`：任一检查为 `failed`。

`DECIDED`：

- 只有 `passed` 可以令 `report.ok === true`。
- `partial` 必须打印醒目摘要并以非零状态退出，不能被显示为绿色通过。
- “未发现长会话”是 `skipped`，不是成功，也不自动触发数据库造数。

## 4. 必需修复契约

### 4.1 E2E-CHECK-01 / P1-5：必需元素检查统一返回失败数组

锚点：`apps/miniapp/e2e/runtime-ui-authenticated.mjs` 的 `checkRequiredElement` 与 `inspectPage`。

`REQUIRED`：

- `checkRequiredElement` 的每一种成功或失败路径都返回 `Failure[]`。
- 选择器缺失时返回一个失败项，至少包含 `label`、实际尝试的选择器和 `reason`。
- `inspectPage` 使用展开语法收集结果时不得抛出 `result is not iterable`。
- 一个缺项不得阻止同页其他独立检查继续执行；最终失败集合应尽量完整。
- 只有非预期异常才能进入 `page inspection` 兜底失败。

验收：

- 人为使用不存在的选择器时，报告明确出现 `required selector missing`。
- 同页其他必需要素仍被检查，报告不再出现 `is not iterable`。

### 4.2 E2E-DETAIL-01 / P1-6：角色详情断言对齐当前结构

锚点：

- `apps/miniapp/src/pages/character/detail.tsx`
- `packages/miniapp-ui/src/components/character/CharacterDetailHero.tsx`
- `packages/miniapp-ui/src/components/character/BondProgress.tsx`
- `apps/miniapp/e2e/runtime-ui-authenticated.mjs` 的 `auth-character-detail` 与 `auth-moon-tower-character-detail`

`REQUIRED`：

- 删除页面中已不存在的 `.detail__section--script`、`.detail__section`、`.character-detail-hero__quick-row` 和 `.character-detail-hero__tools` 断言。
- 两处角色详情检查改用当前结构验证 hero、角色介绍、世界观、人物关系、底部固定区和模式按钮。
- 对带所属剧本的测试角色，世界观区域必须存在并有可读文本；无剧本状态不得被强制渲染空区域。
- 模式按钮数量应由 `availableModes` 驱动；至少验证真实渲染出的按钮具有“进入剧本”或“自由聊天”文案。
- 不得通过移除检查来规避失败；只移除已删除结构，并为当前结构建立等价断言。

验收：

- 白藏与程聿怀详情页均通过当前选择器检查。
- 两条页面检查不再出现失效选择器或静默跳过的布局对。

### 4.3 E2E-HOME-01 / P1-8：默认首页与搜索结果分开断言

锚点：`apps/miniapp/e2e/runtime-ui-real-data.mjs` 的 `checkRealHome`，以及 `apps/miniapp/src/pages/home/index.tsx`。

`REQUIRED`：

- 默认首页只要求剧本 hero、页码点和剧本列表；不得强制要求 `.theater-home__poster-card`。
- 默认首页继续校验 DOM 剧本标题集合与真实 `/api/scripts` 一致，禁止 mock 幽灵剧本。
- 搜索结果作为独立状态验证：先输入可命中的查询，再检查角色海报或明确的空态。
- 搜索态的角色必须来自真实 `/api/characters` 数据域，不得以 mock 角色或静态幽灵数据通过。
- 默认态和搜索态分别保存截图与检查名，禁止用一次截图代表两个状态。

验收：

- 真实 API 默认首页无角色搜索时仍能通过。
- 搜索命中时验证角色海报；搜索无结果时验证空态，不得二选一混淆。

### 4.4 E2E-CHAT-01 / P1-9：真实对话只接受真实助手回复

锚点：`apps/miniapp/e2e/runtime-ui-real-data.mjs` 的 `checkRealChatTurn`，以及 `packages/miniapp-ui/src/components/chat/ChatBubble.tsx`。

`REQUIRED`：

- 等待新增的 `.chat-bubble-row--assistant`，不能只检查“最后一个气泡文本非空”。
- 助手气泡文本必须非空，且不得是用户输入回显。
- 新增回复中不得存在 `.chat-bubble__fallback`，不得显示“本地模式”。
- 页面不得存在 `.chat-page__stream-error`。
- 若 E2E 能观测到流式 `done` 事件，`blocked`、`outOfScope`、`fallback` 任一为真都必须判失败；`fallback` 优先于文本非空。
- 90 秒内未得到合规助手回复时按超时失败，不得继续记 `ok: true`。

验收：

- mock fallback 或流式错误场景不能通过真实对话成功检查。
- 正常真实 LLM 回复仍能通过，并记录助手文本和气泡数量。

### 4.5 E2E-SKIP-01 / P1-10：skip 不得显示全绿

锚点：`apps/miniapp/e2e/runtime-ui-real-data.mjs` 的 `checkRealChatHistory`、报告汇总与 `apps/miniapp/e2e/README.md`。

`REQUIRED`：

- 不存在超过 50 条消息的真实会话时，记录 `status: skipped`，不得记录 `ok: true`。
- 终端摘要和 `report.json` 都显示 `partial` 或 `skipped`，并明确分页断言未验证。
- 整体 `report.ok` 仅在所有必需检查 `passed` 时为真。
- 后端真实 PostgreSQL 51 条分页测试继续存在；缺少 `DATABASE_URL` 时该测试自身 skip，不得表述为已验证。
- 不新增造数或伪造长会话的旁路。

验收：

- 删除或隔离长会话后，真实 E2E 返回非零并显示 `partial`。
- 存在合规长会话时，分页检查能执行并得到 `passed`。

### 4.6 BUILD-PROVENANCE-01 / P1-7：真实 E2E 校验构建变体

锚点：`apps/miniapp/e2e/runtime-ui-real-data.mjs` 的 `ensureDistBuiltForRealApi`、`apps/miniapp/config/index.ts` 与 miniapp 构建脚本。

`DECIDED`：

- 构建产物的可信身份使用机器可读 sidecar，不从 bundle 文本猜测布尔常量。
- sidecar 位于 `dist` 之外，不进入微信代码包；具体路径由实现固定并加入 gitignore。
- sidecar 至少记录：
  - `schemaVersion`
  - `buildProfile`：`development | production | visual-fixture`
  - `apiBaseUrl`
  - `devAuthBypass`
  - `visualFixtures`
  - 构建完成时间（仅诊断，不参与匹配）

`REQUIRED`：

- 所有会生成或覆盖 `dist` 的正式命令都写入 sidecar，包括开发、生产、视觉 fixture 和视觉 runner 的自动重建路径。
- 真实数据 E2E 的期望上下文为：
  - `buildProfile: development`
  - `apiBaseUrl: http://127.0.0.1:3000`
  - `devAuthBypass: true`
  - `visualFixtures: false`
- sidecar 缺失、字段缺失、版本不支持或任一字段不匹配时，真实 E2E 必须重建，不得仅因 bundle 中出现 API URL 就复用。
- 构建失败或 metadata 写入失败必须终止，不得留下可被误复用的半成品身份。

验收：

- 同一 API URL 下的 visual-fixture 构建、凭据开关不同的构建和开发/生产构建不能互相复用。
- 使用错误 sidecar 启动真实 E2E 时，runner 会明确输出期望值与实际值并重建。

### 4.8 PACKAGE-BUDGET-01 / P2-13：CSS 膨胀与真实主包预算分开处理

锚点：

- `apps/miniapp/dist/pages/chat/list.wxss`
- `apps/miniapp/dist/pages/community/index.wxss`
- `apps/miniapp/dist/pages/profile/index.wxss`
- `apps/miniapp/scripts/verify-weapp-build.mjs`
- `apps/miniapp/scripts/verify-visual-assets.mjs`

当前事实：

- 上述生成 WXSS 分别约 `437,695 B`、`435,942 B`、`452,694 B`。
- `2,085,093 B` 是当前 `dist/assets` 大小，不是主包大小；不能继续使用“主包约 2040 KiB”的措辞。
- 当前 `app.json` 没有分包。

`REQUIRED`：

- 从 SCSS import、组件样式注入和构建输出层定位重复公共样式，不得直接编辑 `dist`。
- 生产构建报告同时记录：
  - 可上传主包总字节数
  - 各子包字节数（无分包时为 0）
  - `dist/assets` 字节数
  - 单帧资源预算
- 主包预算校验移入或接入 `verify-weapp-build`，按整个 miniprogram 上传根目录统计，而不是只统计 `assets`。
- `verify-visual-assets` 继续负责 manifest、单图、单帧和资源目录预算，但错误文案与字段必须明确标注为 assets，不得冒充主包。
- 主包硬上限保持 `2 * 1024 * 1024 = 2,097,152 B`，不得放宽。
- 统计文件集必须与项目上传配置一致；`.map` 是否计入由 `project.config.json` 的上传设置和实际打包行为决定，并在报告中写明。
- 若仅去重公共 CSS 仍无法满足主包预算，可将非首屏页面或资源迁入子包；不得删除功能、修改支付/聊天行为或提高阈值。

验收：

- 生产构建生成可复现的主包字节数，来自所有上传文件而非资源目录。
- 主包超过 2 MiB 时 `verify:weapp` 失败。
- 三份大 WXSS 的重复公共样式被移除，并记录修改前后大小。

## 8. 收口条件

3. 认证态 E2E 在正确构建上通过。
