# 首页剧本横幅重复导航修复 Spec

> 状态：`FROZEN / IMPLEMENTED / VERIFIED`
> revision 2 · 2026-11-04 · 合入基线提交 `edd4352`
> 适用范围：`apps/miniapp/src/pages/home/index.tsx` 顶部剧本 Hero 横幅及其回归测试。

## 1. 目标

确保用户点击首页顶部剧本横幅任意位置时只执行一次页面导航：进入所选剧本的选角页一次，不重复推入页面，不产生“页面重新打开/刷新”的视觉反馈。

## 2. 已确认事实

- 顶部剧本卡片的根节点绑定 `onTap={() => chooseRole(script)}`。
- 卡片内部的“选择角色”按钮又绑定了一次相同的 `onTap={() => chooseRole(script)}`。
- `chooseRole()` 内部直接执行 `Taro.navigateTo()`，没有请求防重或导航防重。
- 微信小程序 `tap` 事件会从内层元素冒泡到外层卡片；点击内部按钮会同时触发两个处理器，执行两次 `navigateTo`。
- 重复导航会向页面栈压入两个相同的 `pages/script/select` 实例；用户可能看到选角页再次加载，返回时也需要返回两次。
- 从选角页返回首页时，`useDidShow` 会刷新首页角色数据；这是既有后台刷新行为，不是本次重复导航的主因。

## 3. 范围与边界

### 3.1 REQUIRED

- 顶部 Hero 卡片的根节点继续作为整个卡片区域的唯一点击入口。
- 内部“选择角色”按钮保留现有视觉、文案和点击命中体验；它必须阻止事件继续冒泡，并自行调用 `chooseRole(script)` 一次。
- 点击 Hero 卡片封面、标题、描述或“选择角色”区域，均只能调用一次 `chooseRole(script)`。
- 一次 `navigateTo` 只能向页面栈增加一层 `pages/script/select`。
- `supportsScriptMode === false` 的剧本仍不得进入选角页。
- 点击后目标路由仍为 `getScriptRoleSelectUrl(script.id)`，不得改变路由、参数或页面跳转方式。
- 从选角页返回一次必须直接回到首页。
- 首页原有的 `useDidShow` 静默数据刷新行为保持不变。
- 增加回归检查，锁定外层卡片和内部按钮各自的导航责任，防止任一一次点击最终执行两次 `chooseRole`。

### 3.2 DECIDED

- 内层按钮使用 `event.stopPropagation?.()` 后执行一次 `chooseRole(script)`；外层卡片负责按钮之外的卡片区域。
- 保留两层处理器是事件边界设计，不是重复导航；每次实际手势只能执行一次 `chooseRole`。
- 不使用 `pointer-events` 或删除内层处理器碰运气依赖父级冒泡；DevTools 回归已证明这两种方式会让 CTA 失效。
- 不把内层按钮改成另一种导航封装，不新增页面跳转服务。
- 不以定时器、动画锁定或人为延迟掩盖重复导航。
- 不修改首页 Hero 的视觉布局、标题、描述、按钮样式或轮播行为。
- 不在本 Spec 中增加全局导航队列、全局防抖或路由重写。

### 3.3 非目标

- 不修改剧本列表、剧本目录、选角页或角色详情页的业务逻辑。
- 不修改首页角色数据刷新策略；该问题由 Tab 页面生命周期 Spec 单独处理。
- 不修改 `Taro.navigateTo`、页面栈上限或微信事件模型。
- 不处理用户连续快速点击不同剧本卡片造成的其他导航行为。

## 4. 唯一实现契约

顶部 Hero 的点击责任按事件边界分层，但每次手势只导航一次：

```text
Hero 卡片 onTap
└─ 调用 chooseRole(script) 一次

内部“选择角色” onTap
├─ event.stopPropagation?.()
└─ 调用 chooseRole(script) 一次
```

点击内层按钮时，内层处理器阻止事件冒泡，因此外层不会再次执行；点击卡片其他区域时，只执行外层处理器。

若回归测试证明用户快速双击同一卡片仍会产生重复页面，应另行评审是否增加同步导航锁；本 Spec 不预先引入该状态。

## 6. 验收标准

### 6.1 交互

- 点击 Hero 卡片封面区域：只进入选角页一次。
- 点击 Hero 标题或描述区域：只进入选角页一次。
- 点击“选择角色”文字或按钮区域：只进入选角页一次。
- 进入选角页后返回一次，直接回到首页。
- `supportsScriptMode === false` 的剧本点击后仍停留在首页。

### 6.2 页面栈

- 从首页进入选角页前后，页面栈只增加一个 `pages/script/select` 实例。
- 连续从首页进入同一剧本两次，必须是两次独立的用户操作，不能由一次点击造成两个实例。

### 6.3 回归检查

- 静态测试必须证明外层卡片调用 `chooseRole(script)`，内部按钮先调用 `event.stopPropagation?.()` 再调用一次 `chooseRole(script)`。
- 独立 E2E 分别点击“选择角色”按钮和 Hero 卡片主体，断言页面栈只增加一层 `pages/script/select`。
- 独立 E2E 不修改原 `runtime-ui.mjs` 的十页流程，避免把开发者工具的截图协议超时混入本修复结论。
- 现有首页布局、Hero 轮播、搜索和剧本列表测试保持通过。

## 7. 风险与回撤

| 风险 | 控制措施 |
| --- | --- |
| 内层处理器未阻止冒泡 | 静态测试锁定 `stopPropagation`，E2E 断言页面栈只增加一层 |
| `stopPropagation` 在部分自动化事件对象中不存在 | 使用可选调用；真实小程序事件仍会执行阻止冒泡 |
| 快速双击继续制造重复页面 | 先验证是否仍有问题，再评审同步导航锁；不预先增加全局状态 |
| 返回后首页数据刷新被误判为重复打开 | 检查页面栈与 loading 状态；`useDidShow` 静默刷新保持原样 |

回撤只恢复内层按钮原先无阻止冒泡的 `onTap={() => chooseRole(script)}` 并移除对应回归断言；不得回滚其他首页视觉或数据加载改动。

## 8. 数据与接口

本 Spec 不新增或修改 API、数据模型和服务端行为。目标路由与参数继续由现有 `getScriptRoleSelectUrl(script.id)` 生成。
