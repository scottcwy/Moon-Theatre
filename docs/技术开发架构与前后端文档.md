## 1. 项目概述

本项目是一个基于微信小程序的剧本杀角色扮演产品。用户选择剧本和角色后，可以在剧本模式或自由聊天模式下与角色进行 AI 对话。系统会保存会话历史，并基于对话维护记忆、角色羁绊、成就和点数消费记录。

项目采用 pnpm monorepo，包含：

| 模块 | 目录 | 主要职责 |
| --- | --- | --- |
| 正式小程序 | `apps/miniapp` | Taro + React 微信小程序客户端 |
| UI Playbook 小程序 | `apps/miniapp-playbook` | 独立预览公共 UI 组件，不连接业务 API |
| 业务 API | `apps/api` | Next.js API、AI 对话、用户、支付和管理后台 |
| 共享契约 | `packages/shared` | 跨端类型、常量、支付 Schema 和 Provider 接口 |
| 公共 UI | `packages/miniapp-ui` | 可复用的小程序 UI 组件和设计 tokens |

### 1.1 总体架构

```text
微信小程序 apps/miniapp
        |
        | HTTPS / JSON / NDJSON
        v
Next.js API apps/api
        |
        +--> Drizzle ORM --> PostgreSQL
        |
        +--> FastClaw --> LLM Provider
        |
        +--> 微信登录服务
        |
        +--> 支付 Provider
        |
        +--> Admin 页面和 Admin API
```

公网只应暴露 API 服务。PostgreSQL 和 FastClaw 通过 Docker 内网通信，不直接暴露给小程序。

### 1.2 技术栈

| 层级 | 技术 | 说明 |
| --- | --- | --- |
| 小程序 | Taro 4、React 18、TypeScript、SCSS | 编译为微信小程序；H5 Playground 仅用于设计核对，不是 C 端 H5 产品 |
| API 服务 | Next.js 15、React 19、TypeScript | 使用 App Router 和 Route Handlers |
| 数据库 | PostgreSQL | 业务主数据库 |
| ORM | Drizzle ORM | Schema、Migration 和类型化查询 |
| 请求校验 | Zod | API 请求体和支付数据校验 |
| AI 服务 | FastClaw | OpenAI-compatible Chat Completions 接口 |
| 支付 | Payment Provider 抽象 | 当前支持 mock 和 aggregate Provider |
| 工程化 | pnpm workspace、Docker Compose | 本地开发和部署 |
| 测试 | Vitest、微信开发者工具自动化 | 单元测试、路由测试和小程序 E2E |

## 3. 前端架构

### 3.1 小程序入口和页面

小程序入口配置位于 `apps/miniapp/src/app.config.ts`，运行时入口位于 `apps/miniapp/src/app.ts`。

| 页面 | 路径 | 作用 | 主要接口 |
| --- | --- | --- | --- |
| 首页 | `pages/home/index` | 浏览剧本和角色 | `GET /api/scripts`、`GET /api/characters` |
| 剧本目录 | `pages/script/catalog` | 剧本目录和搜索 | `GET /api/scripts` |
| 剧本选择 | `pages/script/select` | 查看剧本详情和角色 | `GET /api/scripts/:id` |
| 角色详情 | `pages/character/detail` | 查看身份、关系和聊天模式 | `GET /api/characters/:id` |
| 聊天页 | `pages/chat/index` | 查看历史、发送消息、切换模式 | 会话、消息、余额、聊天流接口 |
| 聊天列表 | `pages/chat/list` | 按角色聚合聊天入口 | `GET /api/chat/characters` |
| 社区 | `pages/community/index` | 当前为社区入口占位页 | 当前未接独立社区 API |
| 我的 | `pages/profile/index` | 用户资料、余额、成就和导航 | `/api/me`、余额、成就 |
| 登录 | `pages/login/index` | 微信登录和开发调试登录 | `POST /api/auth/wechat-login` |
| 购买额度 | `pages/quota/buy` | 查看额度包和创建订单 | 额度包、余额、订单、预支付 |
| 支付结果 | `pages/quota/result` | 查看订单状态 | `GET /api/orders/:id` |
| 分享预览 | `pages/share/preview` | 生成角色分享图 | `GET /api/characters/:id` |

底部 Tab 为：首页、聊天、社区、我的。角色、聊天、购买和分享等页面使用普通页面跳转。

### 3.2 前端分层

```text
页面 pages/*.tsx
  |
  +--> 页面状态和交互：useState / useEffect / useDidShow
  |
  +--> 页面纯逻辑：同目录 *.model.ts
  |
  +--> 业务请求：src/services/api.ts
  |
  +--> 公共组件：@juben-sha/miniapp-ui
  |
  +--> 跨端类型和常量：@juben-sha/shared
```

当前没有引入全局状态管理库。登录态保存在 Taro Storage 中，页面通过 API 重新校验和刷新用户信息。

### 3.3 API 客户端

核心文件：`apps/miniapp/src/services/api.ts`

职责包括：

- 统一拼接 `API_BASE_URL` 和接口路径。
- 从本地 Storage 读取 token，并注入 Bearer Authorization。
- 统一处理网络错误、HTTP 错误和 401 登录过期。
- GET 请求对超时、abort、socket hang up 做有限重试。
- 提供 `streamChat` 处理微信小程序分块响应。
- 通过 `clientMessageId` 支持聊天发送失败后的查询和重试。

### 3.4 登录态

```text
Taro.login()
  -> POST /api/auth/wechat-login
  -> API 请求微信 code2session
  -> 创建或更新 users
  -> 返回 7 天 JWT
  -> 小程序保存 auth_token 和 auth_user
  -> 后续请求携带 Authorization
```

开发环境可以通过 `DEV_AUTH_BYPASS=true` 使用调试用户。后端只在非生产环境允许该 token。

### 3.5 前端聊天流程

```text
进入聊天页
  -> 加载角色详情、会话列表、历史消息和余额
  -> 根据 mode 选择剧本模式或自由聊天
  -> 生成 clientMessageId
  -> 乐观插入用户消息和 typing 状态
  -> POST /api/chat/stream
  -> 解析 status / delta / done / error
  -> 成功后更新消息、情绪、羁绊和余额
  -> 失败后按错误码决定重试、对账或跳转购买页
```

服务端当前返回头中的 `X-Stream-Mode` 为 `moderated-buffered`。这表示服务端会先缓冲、清洗和审核完整回复，再返回可展示内容，不是逐 token 直接透传。

## 4. 后端架构

### 4.1 HTTP 层

API 路由位于 `apps/api/src/app/api/**/route.ts`，主要负责：

- 读取请求参数和 JSON body。
- 使用 Zod 校验输入。
- 调用认证中间件。
- 调用领域模块或必要的数据库查询。
- 将结果转换成 HTTP 响应。
- 处理 OPTIONS 和 CORS。

当前路由层整体较薄，但部分列表型接口会直接使用 Drizzle 查询；项目不是严格的 Repository 分层架构。

### 4.2 认证和权限

| 场景 | 认证方式 | 实现位置 |
| --- | --- | --- |
| 普通用户 API | `Authorization: Bearer <JWT>` | `server/middleware/auth.ts` |
| Admin API | 独立管理员邮箱密码登录；HttpOnly `admin_session_v2` cookie | `verifyAdminAuth` → `modules/admin/authentication.ts` |
| Admin 页面 | 同一个 `admin_session_v2` cookie 解析器 | `requireAdminPageAuth`（`modules/admin/page-auth.tsx`） |
| CORS | 微信服务域名和开发环境白名单 | `server/middleware/cors.ts` |

管理员账号独立于小程序用户：`admin_accounts` 保存规范化邮箱、scrypt 密码哈希、`credentialVersion` 和受保护标记；`admin_sessions` 只存 32 字节令牌的 SHA256，8 小时绝对过期。用户 JWT、旧 `admin_session`/`x-admin-session`、`ADMIN_USER_IDS` 白名单、Basic Auth 和开发绕过都不再授予管理身份；旧管理会话由 `0013` 迁移统一撤销。页面与 API 每次请求都重新校验账号有效、凭据版本、会话未撤销/未过期，强制改密期间只允许受限的自查、本人改密和退出。`apps/api/src/middleware.ts` 仅对 `/admin/**`、`/api/admin/**` 追加 `private, no-store` 与安全响应头，不承担授权判定；每个页面和 handler 都有自己的完整守卫。完整契约见 [admin 模块契约](../apps/api/src/server/modules/admin/SPEC.md)。

### 4.3 领域模块

| 模块 | 主要职责 |
| --- | --- |
| `auth` | 微信登录、用户创建、JWT 签发、测试用户赠点 |
| `characters` | 角色列表、角色详情、角色 Prompt 和可用聊天模式 |
| `scripts` | 剧本目录、搜索、剧本详情和角色列表 |
| `chat` | 会话、消息、上下文、幂等、流式生成、完成事务 |
| `fastclaw` | FastClaw OpenAI-compatible API 适配和 fallback |
| `memory` | 记忆抽取、作用域过滤、去重和读取 |
| `relationships` | 羁绊等级、经验和经验事件 |
| `achievements` | 成就规则、称号和解锁 |
| `moderation` | 输入/输出关键词拦截和审核记录 |
| `wallet` | 点数充值、消费、退款、余额锁和幂等 |
| `payments` | Payment Provider、预支付、回调验签和入账 |
| `admin` | 后台统计、会话检索、订单、钱包、审核和模型用量查询；独立管理员账号/会话/密码/CSRF/限速边界（`accounts`、`authentication`、`passwords`、`security`）；角色内容版本与发布（`characters`、`content`）、存量纳管（`character-capture`、`model-capture`）、会话历史（`sessions`） |

### 4.4 AI 调用边界

FastClaw 只负责 Agent 和模型调用，不负责业务状态。

业务 API 负责：

- 用户身份和数据库会话。
- Prompt 上下文拼装。
- 剧本模式和自由模式边界。
- 记忆和羁绊。
- 内容审核。
- 点数扣减和退款。
- 消息落库和幂等恢复。

FastClaw 调用入口为 `apps/api/src/server/modules/fastclaw/adapter.ts`，使用 `/v1/chat/completions`。

## 5. 核心业务流程

### 5.1 聊天流程

接口入口：`POST /api/chat/stream`

```text
1. JWT 认证和请求体校验
2. 校验 characterId、sessionId、mode、scriptId 的一致性
3. 通过 clientMessageId 查询是否已有同一轮消息
4. 在受理事务内固定版本：写入 chat_turn_snapshots（角色已发布内容版本 + 已发布模型档位版本 + 计费档位/单价）
5. 创建或恢复 active chat session
6. 保存 user message，并设置生成状态和 lease
7. 输入关键词审核
8. 加载固定版本的人设/剧本卡片、记忆、羁绊和 preferredName
9. 检查余额并预扣点数
10. 调用 FastClaw
11. 清洗内部语言、解析 mood
12. 剧本模式下执行范围分类
13. 输出关键词审核
14. 保存 assistant message 和 model_usage_logs
15. 成功时增加羁绊经验
16. 触发记忆提取和成就解锁
17. 返回 done 事件和 balanceAfter
```

失败、超时、输出过滤或越界时，会根据场景退款；输入在预扣之前被拦截时不会扣点。第 4 步无法固定版本时（角色未上架/无发布指针、已发布内容不再通过校验、档位无已发布版本），请求在预扣点数前返回 `409` 且不写快照、不落消息；重试、租约接管和进程重启后始终读首次固定的版本，旧回合无快照则保持“版本未知”。

### 5.2 剧本模式和自由模式

| 模式 | `mode` | `scriptId` | 上下文规则 |
| --- | --- | --- | --- |
| 剧本模式 | `script` | 必填 | 注入剧本世界观、剧情 Prompt 和当前剧本记忆 |
| 自由聊天 | `free` | 必须为空 | 保留角色身份和性格，不强制推进剧情，只读取共享记忆 |

同一个用户和角色的两种模式使用不同会话和不同剧情上下文。聊天列表可以按角色聚合入口，但不会合并两种模式的历史。

### 5.3 记忆和聊天完成后效果

assistant 消息保存成功后，会触发：

- 用户信息记忆提取。
- 关系记忆提取。
- 剧情记忆提取。
- 成就和称号解锁。

记忆有两个作用域：`shared` 和 `script`。自由模式只读取共享记忆；剧本模式读取共享记忆和当前剧本记忆。

`chat_effect_runs` 用于记录效果执行状态，支持 lease、失败重试和避免同一 assistant 消息重复执行。

### 5.4 点数和支付流程

```text
额度包列表
  -> 创建订单
  -> 创建预支付参数
  -> 微信/支付 Provider 完成支付
  -> 支付回调验签
  -> 更新订单和 payment 状态
  -> 使用订单级幂等 key 入账钱包
  -> 小程序查询订单结果和余额
```

聊天消费采用“生成前预扣，失败或过滤退款”的策略。钱包交易使用数据库事务和幂等 key，避免重复扣点或重复入账。

## 6. 数据库架构

数据库连接和表定义位于：

- `apps/api/src/server/db/index.ts`
- `apps/api/src/server/db/schema.ts`
- `apps/api/drizzle/`

### 6.1 数据域

| 数据域 | 主要表 | 说明 |
| --- | --- | --- |
| 用户 | `users` | 微信 openid、昵称、头像、preferredName、状态 |
| 内容 | `scripts`、`characters`、`character_prompts` | 剧本、角色和角色 Prompt |
| 剧情 | `scenes`、`story_nodes`、`user_story_state` | 当前为剧情扩展数据模型 |
| 对话 | `chat_sessions`、`messages` | 模式会话、消息、生成状态和审核标记 |
| 记忆关系 | `memories`、`relationships` | 共享/剧本记忆和角色羁绊 |
| 成长 | `achievements`、`titles`、用户关联表 | 成就和称号 |
| AI 用量 | `model_profiles`、`model_usage_logs` | 模型档位、价格、调用和消费记录 |
| 钱包支付 | `wallet_accounts`、`wallet_transactions`、`quota_packages`、`orders`、`payments` | 余额、额度包、订单和支付状态 |
| 审核 | `blocked_keywords`、`review_logs` | 关键词规则和审核记录 |
| 内容版本 | `content_versions`、`characters.published_version_id`、`publish_tasks` | 角色/剧本草稿与已发布快照、唯一发布指针、发布任务与恢复状态 |
| 回合版本 | `chat_turn_snapshots` | 已受理回合的内容版本、模型档位版本、provider/model 与单价快照 |
| 模型版本 | `model_profiles`、`model_profile_versions` | 计费/展示配置及其不可变版本（批 2 为存量档位补首个已发布版本） |
| 管理身份 | `admin_accounts`、`admin_sessions`、`admin_login_limits` | 独立管理员账号、哈希会话令牌、登录限速窗口；历史用户/审计列保留 |

### 6.2 关键数据库约束

- `users.openid` 唯一。
- `wallet_accounts.userId` 唯一。
- `wallet_transactions.idempotencyKey` 唯一。
- 一个用户和角色在同一聊天模式下只有一个 active session。
- `script` session 必须有 `scriptId`。
- `free` session 不允许有 `scriptId`。
- `script` 类型 memory 必须有 `scriptId`。
- 相同 session、role、clientMessageId 的用户消息不能重复创建。
- 同一 `(entity_type, entity_id)` 最多一条 `content_versions` 行 `status='published'`（部分唯一索引 `content_versions_entity_published_unique`）；`characters.published_version_id` 外键指向 `content_versions.id`，它是新回合唯一读取的发布指针。
- 每个 user message 最多一条 `chat_turn_snapshots`（`user_message_id` 唯一），`content_version_id`/`model_profile_version_id` 非空外键；没有任何快照的旧回合保持“版本未知”，不倒推。
- 内容/模型版本创建者列从“恰好一人”放宽为“至多一人”：`NULL/NULL` 只用于服务端纳管捕获，管理员写入仍必须恰好一个创建者。
- `admin_accounts.email` 规范化（trim + 小写）后唯一；`is_protected = true` 最多一行。
- `admin_sessions` 新行必须且只能关联 `admin_account_id`，`token_hash` 唯一；历史用户会话行保留但已撤销。
- 审计、内容/发布/模型版本创建者、钱包流水管理员和审核员都保留旧用户列，并用独立 `admin_account_id`（或等价新列）记录新身份；两类身份列不得同时写入。

### 6.3 迁移 0014/0015 与存量纳管

`0014_character_publishing.sql`（additive）：`characters.published_version_id` 与外键、每实体最多一条已发布的 `content_versions_entity_published_unique` 部分唯一索引、`chat_turn_snapshots(character_id, content_version_id)` 索引，并将 `content_versions_creator_check` 从“恰好一个创建者”放宽为“至多一个”；同文件把存量内容纳管为首个已发布版本。`0015_turn_version_pinning.sql`（additive）：`chat_turn_snapshots.client_message_id` 改为可空（旧客户端不提供该字段），同样放宽 `model_profile_versions_creator_check`，并为从未有过版本行的模型档位捕获一个已发布版本行，使已受理回合能固定 `model_profile_version_id`。

纳管规则是“捕获，不编造”（同一套语句两处调用，`apps/api/src/server/modules/admin/character-capture.ts` / `model-capture.ts` 与迁移文件逐字一致，测试会因漂移失败）：只捕获 `status='active'` 且没有发布指针的角色（后台新建的草稿角色本就 `inactive`，给它发明一个发布等于伪造证据）；每个角色只得到一个 `published` 版本，payload 取自现有展示行 + 最新 `character_prompts` 行 + 绑定剧本卡片，`version_no` 接续既有链，`content_hash` 按存储 payload 文本计算；创建者列为 `NULL/NULL`（无真人作者）；已有发布快照的无指针角色只“认领”既有快照，不会多出一条；重跑不插入任何行。`seed()` 在插入角色与模型档位后调用同一个捕获单元，所以 `migrate → seed` 的全新库中每个 seed 角色都已可聊天，而不是留着空指针被回合拒绝。

已知限制：`0014`/`0015` 与 `0011`–`0013` 一样是手写 SQL（只改 `_journal.json`，没有生成的 drizzle snapshot）；`config_hash` 仍有两套不兼容算法（`models.ts` 对 `JSON.stringify(model)` 取哈希，`0015` 捕获对 `{profileId,provider,modelName,pointsPerCall}` 取哈希），本批未统一。

### 7.2 Admin 接口和页面

Admin API 位于 `/api/admin/**`，页面位于 `apps/api/src/app/admin/**`；两者共用独立管理员会话，全部写入强制 Origin + JSON + `X-Admin-Request: 1`，响应 `private, no-store`。接口覆盖：

- 统计数据。
- 管理员账号：登录/会话、账号列表与创建、停用、重置密码、本人改密/改邮箱。
- 会话和消息：可按用户/角色/模式/状态/创建日期范围筛选；正文分页读（`/sessions/:id/messages`）并返回每轮版本归属。
- 角色内容版本：列表、创建草稿、首个草稿、保存草稿（基准版本/时间）、发布、下架、展示预览（默认最新草稿）；发布任务与模型发布的 finalize-only 审计收尾。
- 订单、支付和钱包（含仅收尾审计的调账恢复接口）。
- 额度包配置。
- 模型调用日志。
- 敏感词和审核记录。

页面为 18 个动态路由：原 9 个业务入口（`/admin`、sessions、orders、payments、wallet、quota-packages、model-usage、blocked-keywords、review-logs）加批 2 的 5 个（`/admin/characters`、`/admin/characters/new`、`/admin/characters/[id]/edit`、`/admin/characters/[id]/preview`、`/admin/sessions/[id]`），再加 `/admin/login`、`/admin/change-password`、`/admin/accounts`、`/admin/account`。登录与改密页不进入私有 `(console)` layout；`(console)` layout 只做跳转边界，每个页面查询前仍独立调用完整守卫。角色列表把发布状态、草稿差异与最近发布任务分三列，编辑页分“展示资料/角色人设/开场引导/预览与发布”四段；新建只产草稿，预览只展示不聊天，发布/下架需显式勾选确认，超过 30 秒只能显示“处理中”或“已提交，审计待恢复”。聊天历史页显示“版本 vN”并链到该版本预览，无快照的旧记录显示“版本未知”。旧 Memories 页面/导航已退场且 PATCH 返回 `410`，不新增记忆界面，也没有上传、删除角色或模型档位控制台。

### 7.3 关键错误码

| HTTP / code | 含义 | 客户端处理建议 |
| --- | --- | --- |
| `401` / `AUTH_EXPIRED` | 登录失效 | 清理本地 token，跳转登录 |
| `402` / `insufficient_points` | 点数不足 | 跳转额度购买页 |
| `409` / `session_scope_mismatch` | 会话模式或剧本不一致 | 重新加载会话元数据 |
| `409` / `script_unavailable` | 剧本或角色已下架 | 展示只读或不可发送状态 |
| `409` / `client_message_id_collision` | 客户端消息 ID 冲突 | 生成新的 clientMessageId |
| `409` / `character_version_unavailable` | 回合无法固定到已发布角色版本（角色未上架/无发布指针/指针不一致/无快照的旧回合重试） | 不扣点；先在后台发布该角色，旧回合保持版本未知 |
| `409` / `character_content_incomplete` | 已发布版本无法重过内容校验（如纳管的旧内容缺人设） | 保存完整草稿并重新发布 |
| `409` / `model_profile_unavailable` | 所选档位已启用但没有已发布模型档位版本（档位不存在/未启用是预检 `400`） | 先发布模型档位；不扣点 |
| `in_progress` | 同一轮请求仍在处理 | 等待或调用对账接口 |
| `upstream_error` / `timeout` | AI 上游失败 | 展示可重试状态 |
| `out_of_scope` | 剧本模式下问题越界 | 展示角色内兜底回复 |

## 8. 本地开发、测试和构建

### 8.1 环境要求

- Node.js `>=20`
- pnpm `>=9`
- Docker
- 微信开发者工具（执行小程序 E2E 时需要）
- 本地 PostgreSQL 或 Docker Compose

项目约定 shell 命令使用 `rtk` 前缀。

### 8.2 常用命令

```bash
# 一键启动 PostgreSQL、API、FastClaw 和小程序 watch 构建
rtk pnpm dev

# 分别启动
rtk pnpm dev:api
rtk pnpm dev:miniapp
rtk pnpm dev:playbook

# 构建
rtk pnpm build:api
rtk pnpm build:miniapp
rtk pnpm build:playbook

# 类型检查、Lint、单元测试
rtk pnpm typecheck
rtk pnpm lint
rtk pnpm test

# 数据库
rtk pnpm db:generate
rtk pnpm db:migrate

# 小程序构建产物校验
rtk pnpm --filter @juben-sha/miniapp verify:weapp
rtk pnpm verify:playbook
```

### 8.3 API 地址注入

小程序构建时通过 `API_BASE_URL` 注入 API 地址，域名统一配置在 `apps/miniapp/config/hosts.json`（`dev`/`lan`/`prod`）：

- 开发环境默认使用 `http://127.0.0.1:3000`（`dev`），`pnpm dev:miniapp` 直接可用。
- 真机预览使用 `pnpm dev:miniapp:lan`，读取 `hosts.json` 的 `lan`（需先填入电脑局域网 IP）。
- 生产构建使用 `pnpm build:miniapp:prod`，读取 `hosts.json` 的 `prod`（当前为 `https://api.yuemanlou.xyz`）；仍拒绝 `.invalid` 和占位 API 地址。
- 构建后 `verify:weapp` 会扫描 `dist` 中的文本产物。

不要为了测试生产构建而使用占位 API 地址，也不要让占位地址进入小程序产物。

### 8.4 小程序 E2E

小程序 E2E 位于 `apps/miniapp/e2e/`，具体命令和端口以 `apps/miniapp/e2e/README.md` 为准。覆盖：

- 构建产物冒烟检查。
- 微信开发者工具启动。
- 主要页面运行时 UI 检查。
- 调试登录和 mock API。
- 聊天失败、点数不足、额度购买和支付结果页面。
- 13 帧视觉对比工具（当前受开发者工具固定 `390×844` 阻塞，不能宣称视觉门禁通过）。

运行 automator 前必须先彻底退出开发者工具（`cli quit`），让 automator 用 `cli auto` 拉起干净实例；手动开着的 IDE 会与自动化会话抢 App 域，表现为 `App.captureScreenshot` 超时。

## 9. 部署架构

生产部署使用 Docker Compose，服务包括：

| 服务 | 作用 |
| --- | --- |
| `postgres` | PostgreSQL 数据库 |
| `api` | Next.js 业务 API 和 Admin 页面 |
| `api-migrate` | 执行 Drizzle migration |
| `api-seed` | 初始化剧本、角色、模型和额度包数据 |
| `fastclaw` | AI Agent 和模型调用 |
| `caddy` | HTTPS、域名入口和反向代理 |

标准部署顺序：

```text
拉取镜像
  -> 启动 PostgreSQL 和 FastClaw
  -> 执行数据库迁移
  -> 执行 seed
  -> 创建首个管理员（服务器命令，密码经隐藏输入/标准输入传入）
  -> 启动 API 和 Caddy
  -> 检查 /api/health 和 /api/ready
  -> 使用真实 HTTPS API 地址构建小程序
  -> 执行 verify:weapp
```

`ADMIN_ORIGIN` 是管理写入的同源基准：生产必须显式设为 `https://api.yuemanlou.xyz`，开发默认 `http://localhost:3000`。只需一个 `reverse_proxy api:3000`，Caddy 额外用 `header_up X-Admin-Client-IP {remote_host}` 覆盖客户端同名头；API 端口不对外发布。若将来在 Caddy 前增加 CDN/代理，必须重新评审这条单跳信任边界。

详细操作和环境变量说明维护在 `docs/deployment.md`。

## 10. 当前架构边界和待补事项

以下内容是当前代码边界，不应在开发文档中误写成已完成能力：

1. 聊天目前是 `moderated-buffered`，不是未经审核的逐 token 直出。
2. 社区页面目前主要是占位入口，尚未形成独立社区后端模块。
3. `miniapp-playbook` 是独立组件预览小程序，不是业务页面。
4. Admin 首批（独立管理员身份、账号生命周期、中文品牌框架与 13 个动态页面路由）与批 2（角色内容版本/发布、存量纳管、回合版本固定、会话筛选与分页正文+版本归属，共 18 个动态页面路由）代码已实现并在本地验证；素材上传、删除角色、用户业务管理、订单补发、套餐与模型配置控制台、通用审计恢复界面仍属后续批次，也未验收。
5. FastClaw、真实支付服务商和生产环境变量仍需要真实环境联调验收。
6. 剧情节点相关表已存在，但当前聊天主流程主要围绕角色、剧本、记忆和会话展开。
7. 当前项目不是严格的 Controller-Service-Repository 三层架构，部分 Route Handler 会直接查询数据库。
